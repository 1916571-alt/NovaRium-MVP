# NovaRium V2 PRD (MVP2)

## 1. 제품 비전
- 같은 시작 플랫폼에서 출발한 사용자가 SQL 분석과 실험을 통해 각자 다른 제품 상태(미니홈)로 진화한다.
- 사용자는 자신의 실험 근거와 의사결정을 커뮤니티에 공유하고, 타인의 전략을 복제/비교하며 학습한다.

## 2. 문제 정의
- 기존 학습 도구는 SQL 분석과 실험 실행이 분리되어 실제 의사결정 루프를 체감하기 어렵다.
- 결과 화면이 고정되어 있어 “채택 경로에 따른 제품 진화”를 경험하기 어렵다.
- 개인 학습이 고립되어 커뮤니티 기반 학습 전이가 약하다.

## 3. 목표
- SQL 문제 발견 -> 병목 진단 -> 실험 -> 채택 -> 사용자별 미니홈 분기까지 하나의 루프로 제공
- 멀티유저/권한/데이터 격리 기반으로 운영 가능한 구조 확보
- 실험 리포트 공유/복제로 커뮤니티 학습 형성

## 4. 비목표 (MVP2 범위 밖)
- 결제/구독
- 기업 SSO
- 복잡한 실시간 스트리밍 인프라

## 5. 핵심 사용자
- 실무형 데이터 분석가 취준생
- 주니어 PM/PO
- 실험 문화 학습이 필요한 개발자

## 6. 사용자 스토리
1. 사용자로서, 공통 시작 템플릿을 받아 동일 출발선에서 시작하고 싶다.
2. 분석가로서, SQL로 이상 징후를 찾아 문제를 명확히 정의하고 싶다.
3. 실험 담당자로서, 가설과 지표를 정하고 A/B 테스트를 실행하고 싶다.
4. 의사결정자로서, 근거를 남기며 채택/기각/부분 롤아웃을 선택하고 싶다.
5. 학습자로서, 채택 누적 결과가 내 미니홈에 반영되어 성장 경로를 보고 싶다.
6. 커뮤니티 멤버로서, 다른 사람 실험을 보고 복제해서 비교하고 싶다.

## 7. 기능 요구사항
### 7.1 인증/권한
- 이메일 기반 회원가입/로그인/로그아웃
- workspace/project 단위 권한 분리 (owner/editor/viewer)
- RLS로 데이터 격리 강제

### 7.2 SQL Lab
- SQL 실행기 (읽기 전용 샌드박스)
- 과제 템플릿 (퍼널 이탈, 세그먼트 급락, 지표 이상)
- 정답 검증 (결과셋/핵심 지표 기준)
- 힌트 및 해설

### 7.3 Funnel/Bottleneck
- 퍼널 정의 생성/수정
- 단계별 전환율, 이탈률, 소요시간 계산
- 병목 자동 탐지 규칙 (임계치 기반)

### 7.4 Experiment Lab
- 가설/변형/지표/가드레일 설정
- 실험 활성화/종료
- 결과 분석 (lift, p-value, CI, SRM)
- 의사결정 로그 (채택/기각 사유 필수 기록)

### 7.5 Adoption Engine
- 채택(승자안) 저장
- 점진 롤아웃 (% 제어)
- 롤백

### 7.6 Minihome Engine
- `start_state` 공통
- adoption별 `state_patch` 누적
- 사용자별 최종 상태 렌더링
- 상태 타임라인 제공

### 7.7 Community
- 실험 리포트 게시
- 댓글/북마크/좋아요
- 실험 복제(Fork) 후 내 프로젝트에서 재실행

## 9. KPI
- SQL 과제 완료율
- 실험 완료율
- 채택률 및 채택 후 지표 개선률
- 실험 리포트 공유율
- 복제 실험 실행율
- 7일/30일 재방문율

## 10. 성공 기준 (MVP2)
1. 신규 사용자가 로그인 후 프로젝트 생성 가능
2. SQL Lab에서 최소 3개 과제 수행 가능
3. 퍼널 병목 자동 탐지 결과 확인 가능
4. 실험 실행 후 채택/롤백 가능
5. 사용자별 미니홈 상태가 분기됨
6. 커뮤니티에서 실험 공유/복제가 가능

## 11. 릴리즈 계획 (8주)
1. 1-2주: Auth + Workspace + RLS
2. 3주: Event ingest + SQL Lab v1
3. 4주: Funnel/Bottleneck
4. 5주: Experiment lifecycle
5. 6주: Adoption rollout/rollback
6. 7주: Minihome divergence
7. 8주: Community + hardening
